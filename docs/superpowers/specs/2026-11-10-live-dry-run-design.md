# Дизайн: живой dry-run прогон (задача 9.4)

Дата: 2026-11-10. Статус: на утверждении.

## Intent

Задача 9.4 (`openspec/changes/core-market-driver/tasks.md`): «Dry-run прогон на
живой игре (без HID): состояния определяются, действия логируются». Первый
живой контакт ядра с игрой: экран читается по-настоящему (MssScreen), детекция
состояний работает на реальных кадрах, все HID-действия идут в DryRunHid как
намерения. Инструменты (8.1 kill switch, 8.2 dry-run, 8.3 JSONL-лог)
реализованы и покрыты тестами; раннера, собирающего их в живой прогон, нет.

## Goals

- `tools/live_dry_run.py` — ручной раннер-зонд (вне CI, как benchmark_ocr.py).
- Принудительный dry-run: `create_api(..., dry_run=True)` независимо от
  конфига; обращений к HID/arduino нет по построению (DryRunHid).
- Kill switch активен на всём прогоне: хоткей (`ctrl+shift+k`, Win32-хук) +
  таймаут неактивности; `cancelled` KillSwitch передаётся в create_api.
- Намерения действий видны в логе `l2core.dry_run`, JSONL ActionLogger
  фиксирует шаги с ключевыми кадрами (не-OK исходы) — обе точки уже есть.

## Non-goals

- Не цикл бота и не CLI стратегии (готовый цикл — вне объёма, AGENTS.md);
  это разовый инструмент приёмки 9.4, не «команда запуска бота».
- Не 9.5 (ручной прогон с реальным HID) — следующий шаг.
- Не запись live-сессии через RecordingScreen: точка уведомления действий
  в живой сборке не проверена; если простой точки подключения нет —
  паркуем (YAGNI), живой прогон 9.4 её не требует.

## Проба (фиксированная последовательность)

1. `health()` — окно игры / окно торговли / OCR / HID(dry) — одна строка.
2. `get_state()` — (window, state, params, status) на живом кадре.
3. `open_market()` — намерение клика по HUD, verify на реальных кадрах.
   Ожидаем FAILED/UNKNOWN (эффекта нет — dry-run), OK допустим, если обзор
   уже был открыт.
4. `get_state()` повторно — состояние после «открытия».
5. Если обзор found: `read_rows()` → `scroll_list("down", 2)` →
   `read_rows()` — чтение таблицы и скролл-намерения.
6. `close_market()` — намерение закрытия.
7. Сводка: увиденные состояния, число намерений, пути логов, итог каждого
   шага (OK / FAILED / UNKNOWN / cancelled / ошибка).

Каждый шаг печатает одну строку; исключение шага фиксируется в сводке, проба
продолжается. Kill прерывает пробу между шагами — сводка печатается.

## Ключевые решения

- **Чекпоинт OCR**: `--model <путь>` побеждает `paths.model` конфига;
  разрешённый путь не существует → понятная ошибка, exit 2 (конвенция
  benchmark_ocr.py). Shipped `config.yaml` не трогаем (== дефолты схемы);
  прогон запускается с `--model
  E:\L2-CRNN-MODEL-TRAIN\runs\20261105-213625\crnn_best.pt`.
- **Kill switch**: `KillSwitch(config.kill_switch, hotkey_source=
  Win32HotkeySource(...), set_cursor_pos=gateway...)`; `hid` подключается
  через `attach()` после create_api (DryRunHid — release_all при kill это
  no-op с логом). `ks.start()` до пробы, `ks.stop()` после (в finally).
- **Структура**: `run_probe(api, out=print) -> ProbeReport` — чистая
  композиция вызовов фасада, тестируемо на подмене; `main()` — argparse +
  живая сборка. Никакой логики детекции в раннере (тонкий, как фасад 7.1).
- **Тесты**: `tests/test_live_dry_run.py` — проба на stub-API:
  последовательность шагов, формат сводки, фиксация исключения шага,
  прерывание по cancelled. Интеграция `create_api(dry_run=True)` уже
  покрыта tests/test_dryrun.py — не дублируем. TDD: тесты первыми.
- **Документация** (правило «вместе с реализацией»): AGENTS.md — команда
  ручного прогона в списке команд (пометка «вне CI»); README — раздел
  Dry-run дополнен командой прогона и ожидаемой семантикой исходов.
- **После успешного живого прогона**: tasks.md 9.4 → `[x]` с заметкой
  (дата, что увидели: определённые состояния, число намерений).

## Constraints

- Игра должна быть запущена, видима и доступна win32-находилке
  (`window.title: Lineage II` из конфига); activate_game пролог работает
  по-настоящему — это часть проверки, а не препятствие.
- Windows + права не ниже игры (DPI-aware объявляет create_api).
- Код и комментарии — на русском; детерминизм тестов (раннер на живом
  экране детерминизму не подчинён — это ручной инструмент, вне CI).

## Что оставляем builder'у

- Точные строки вывода сводки; обработку KeyboardInterrupt в main();
  код выхода 0 (прогон завершён, даже если шаги FAILED — это честные
  исходы dry-run) / 2 (нет чекпоинта, конфиг не читается).
