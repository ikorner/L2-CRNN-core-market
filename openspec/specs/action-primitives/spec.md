## Requirements
### Requirement: Ожидание только по предикату, без sleep
Все примитивы SHALL ожидать изменений через `wait_until(predicate, timeout)` с таймаутами из конфига; прямые вызовы `sleep()` в коде ядра MUST быть запрещены (инвариант AGENTS.md).

#### Scenario: Таймаут ожидания состояния
- **WHEN** предикат не выполнился за таймаут из конфига
- **THEN** примитив возвращает трёхзначный результат с диагностикой и не ждёт дольше

### Requirement: Каждое действие верифицируется, при неудаче — retry → on_fail → recover
Каждое действие (клик, ввод, скролл) SHALL выполнять verify результата (например, вкладка стала active); при verify-fail выполняется retry (число из конфига), затем шаги `on_fail[]` из перехода модели, затем общий recover; клики без verify MUST быть запрещены.

#### Scenario: Успешный клик по вкладке
- **WHEN** выполняется `click_element` по вкладке
- **THEN** после клика verify подтверждает, что вкладка стала active, результат `OK`

#### Scenario: Verify-fail после исчерпания retry
- **WHEN** verify не проходит после всех retry
- **THEN** выполняются шаги `on_fail[]` из модели, затем при неудаче — общий recover

### Requirement: Критичные действия возвращают трёхзначный результат
Критичные действия SHALL возвращать `OK` / `FAILED` / `UNKNOWN`, где UNKNOWN = эффект не подтверждён (лаг, перекрытие); ядро MUST NOT повторять потенциально необратимые действия (начать продажу, подтвердить) при UNKNOWN — решение передаётся стратегии.

#### Scenario: Необратимое действие при UNKNOWN не повторяется
- **WHEN** `start_sell()` вернул UNKNOWN
- **THEN** ядро не повторяет подтверждение и отдаёт результат стратегии

### Requirement: Recover-цепочка с пассивными шагами и эскалацией
Общий recover SHALL следовать цепочке: ESC → клик в свободную область клиента → закрыть окно (если открыто не то) → переоткрыть окно через иконку HUD (open_market / open_shop_buy / open_shop_sell + wait verify открытия) → перекалибровка якоря → эскалация (пауза + событие стратегии); автоматическое перетаскивание окон MUST быть запрещено, клик по заголовку торгового окна для подъёма допустим.

#### Scenario: Recover переоткрывает окно через HUD
- **WHEN** цепочка recover дошла до переоткрытия
- **THEN** выполняется клик по соответствующей иконке HUD и ожидание сигнатуры окна

#### Scenario: Исчерпание цепочки
- **WHEN** все шаги recover не восстановили состояние
- **THEN** ядро переходит в паузу и отправляет стратегии событие `escalation`

### Requirement: Штатный FAILED при невыполненных предусловиях открытия
Если после клика по иконке HUD окно не открылось за таймаут ядро SHALL вернуть штатный FAILED с фиксацией состояния (включая возможную модалку с причиной — зона торговли / персонаж мёртв и т.п.) и MUST отправить событие `escalation` без повторных кликов.

#### Scenario: Лавку нельзя создать в текущей зоне
- **WHEN** после клика по `open_sale_trade` окно не открылось за таймаут
- **THEN** возвращается FAILED, фиксируется состояние/модалка, событие `escalation`, повторных кликов нет

### Requirement: Кэш кадра в рамках транзакции
Детектор SHALL анализировать один и тот же кадр не более одного раза внутри шага (grab → analyze once → решения по свежему кадру); перед необратимым действием SHALL выполняться свежий grab и re-verify цели.

#### Scenario: Re-verify перед необратимым действием
- **WHEN** примитив готовится к необратимому действию (начать продажу)
- **THEN** выполняется свежий захват кадра и повторная проверка цели

### Requirement: Устойчивость к hover и тултипам
Примитивы SHALL учитывать: hover меняет вид элемента до клика (verify после hover-паузы); тултип может перекрыть цель (сдвинуть курсор или подождать исчезновения).

#### Scenario: Тултип перекрывает цель
- **WHEN** verify клика не проходит из-за перекрывающего тултипа
- **THEN** курсор сдвигается/ждётся исчезновение тултипа и действие повторяется в пределах retry

### Requirement: Ввод цены и текста с выбором способа по профилю
Ядро SHALL выбирать способ ввода (клики по экранному нумпаду или клавиатура) по настраиваемому распределению поведенческого профиля; поиск SHALL применяться и Enter, и кнопкой «Поиск» — способ выбирается рандомизацией профиля.

#### Scenario: Выбор способа ввода по распределению
- **WHEN** вызывается ввод цены
- **THEN** способ ввода выбирается по долям из конфигурации профиля

### Requirement: Восстановление раскладки при вводе текста
После набора текста SHALL выполняться OCR поля ввода; при транслите SHALL выполняться backspace + switch_layout + повтор ввода.

#### Scenario: Раскладка переключилась на транслит
- **WHEN** OCR поля после набора показывает транслит вместо ожидаемого текста
- **THEN** выполняется backspace, switch_layout и повторный ввод, затем повторная проверка OCR

### Requirement: Примитив press_key нажимает клавишу с verify и трёхзначным исходом
Система SHALL предоставлять примитив `press_key(key, verify, on_fail, ...)` (5.9): пролог активации окна игры, `hid.key_press`, блокирующий `wait_until` на verify свежих кадров, retry (n из конфига) → `on_fail[]` → общий recover. Исходы по инварианту 4: verify не сошёлся за таймаут → FAILED (эффект отсутствует, повтор безопасен); HID-сбой при нажатии → UNKNOWN (`unconfirmed`). Никаких `sleep` — только `wait_until` с таймаутами из конфига.

#### Scenario: Нажатие с подтверждением результата
- **WHEN** `press_key("X", verify=<сигнатуры menu_open>)` и меню открылось на свежих кадрах
- **THEN** результат OK, действие подтверждено verify

#### Scenario: Клавиша нажата, эффект отсутствует
- **WHEN** `press_key("X", ...)` отработал, но verify не сошёлся за таймаут из конфига
- **THEN** результат FAILED, после retry и шагов `on_fail` — общий recover

#### Scenario: HID-сбой при нажатии
- **WHEN** `hid.key_press` бросил `HidError`
- **THEN** результат UNKNOWN с `unconfirmed=True` (нажатие могло уйти, могло нет)

### Requirement: HID-адаптер знает кейкод клавиши X
HID-адаптер SHALL предоставлять кейкод `KEY_X` (Virtual-Key `X`) для `key_press`. Кейкоды цифр и F-клавиш не добавляются (раскладка quick-slot свободная — открытие лавок кликом по найденной иконке).

#### Scenario: Нажатие X доступно через адаптер
- **WHEN** примитив запрашивает `key_press` с `KEY_X`
- **THEN** адаптер отправляет корректный Virtual-Key код клавиши X
