# Design: menu-quickslot-navigation

Авторитетный источник решений — одобренный дизайн
`docs/superpowers/specs/2026-11-10-menu-quickslot-navigation-design.md`
(builder-check пройден). Ниже — сохранённые решения без переоткрытия;
формулировки сокращены, смысл не менялся.

## Решения владельца (зафиксированы, не переоткрываются)

- Раскладка quick-slot **свободная** → открытие лавок — визуальным поиском
  иконки на панели и кликом; хоткей-путь (1–3/F1-F3) не проектируется,
  кейкоды цифр/F-ключей не добавляются.
- Клавиатура в навигации — только для «Меню»: клавиша **X** (toggle;
  закрывают также ESC и клик вне области), гамбургер — alternate-путь.
- Охват — все три окна: market (через меню), shop_buy и shop_sell (через
  quick-slot); старый сломанный HUD-путь удаляется.

## Выбранный подход

Гибрид (из трёх рассмотренных: полностью-в-модели / навигация-в-коде /
гибрид-рецепты-в-YAML): всё знание об UI навигации — в
`ui_model/navigation.yaml`, код — только исполнитель примитивов. Формат
`states`/`transitions` моделей окон **не меняется**; многошаговые и
межоконные пути выражаются сущностью «рецепт», а не расширением переходов.

## Схема navigation.yaml

Секции (файл — не модель окна, `window`/`states`/`transitions` в нём нет):

- `elements` — те же роли и правила, что в моделях окон:
  `hamburger_button` (HUD, `search_area` справа внизу клиентской области),
  `menu_anchor` (HUD, template рамки/заголовка меню; элементы внутри меню
  1:1 от него — позиция меню не считается фиксированной),
  `menu_market_icon` (rect от `menu_anchor`), `quickslot_buy_icon` /
  `quickslot_sell_icon` (HUD, `search_area` панели быстрого доступа).
- `signatures` — сигнатуры `menu_open` (≥ 2 независимых признака:
  `menu_anchor` + `menu_market_icon`).
- `recipes` — рецепты открытия. Шаг: `action: key|click`, `verify[]`
  (обязателен, непуст), `on_fail[]` (именованные шаги исполнителя —
  тот же словарь, что в `transitions`), опционально `when: [checks]`
  (выполнять только если сошлось) и `skip_if: [checks]`. Проверки
  допускают отрицание `expect: absent`. Рецепт: `opens: <window>`,
  `on_fail[]`, опциональный `alternate` (резервный рецепт после
  исчерпания основного). Retry шага — из конфига (как у click_element).
  Связка с recover-состоянием — соглашение имён: `open_<window>`
  открывает окно из `recover_closed` этой модели.

Пример рецептов — в дизайн-документе (раздел «Схема navigation.yaml»).

## Нормализация «Меню»

Первый шаг рецептов лавок: `key X` с `when: [menu_open]`, verify —
`menu_anchor expect: absent` (закрыть меню, если открыто). Шаг 1
`open_market`: `key X` с `skip_if: [menu_open]` (не закрыть меню
повторным toggle). X — toggle, слепое нажатие опасно; открытие лавок не
зависит от того, пропускает ли игра клики сквозь меню.

## Исполнение (код)

- `l2core/adapters/hid.py`: кейкод `KEY_X` (Virtual-Key `X`).
- Примитив `press_key` (5.9): пролог активации, `hid.key_press`,
  блокирующий `wait_until` на verify, retry → on_fail → общий recover.
  Исходы: verify не сошёлся → FAILED (эффект отсутствует, повтор
  безопасен); HID-сбой → UNKNOWN (`unconfirmed`).
- Исполнитель рецептов (место по слоям определит план): резолв элементов
  (HUD — template matching по `search_area`; элементы меню — по якорю
  меню на свежем кадре), шаги через `press_key`/клик-примитив. Иконка не
  локализована → шаг FAILED **без клика** (слепых кликов нет). Клик ушёл,
  окно не появилось на кадрах → UNKNOWN (как `_open_via_hud`).
  Неудача шага → его on_fail → следующий шаг; исчерпание → on_fail
  рецепта → alternate → общий recover (scenario_recover, 6.4).
- API: `open_market`/`open_shop_buy`/`open_shop_sell` исполняют рецепты;
  `verify` у лавок перестаёт быть обязательным (из рецепта), параметр
  сохранён как override; `_open_via_hud` удалён.

## Предшественники (в скоупе)

1. **Многоопорный якорь (KNOWN_GAPS п. 6)** — кодовый предшественник:
   `anchor_templates: window -> [опоры]`, перебор по порогу окна; чистая
   досъёмка open-окон лавок; импорт кропов заголовков в модели. Без него
   verify рецептов лавок непроверяем (сигнатуры `opening` shop_buy
   нестабильны — KNOWN_GAPS п. 5).
2. **Инструментальная досъёмка quick-slot** — сессия, открывающая shop_buy
   и shop_sell кликом по своим иконкам панели: шаблоны `quickslot_*_icon`
   и подтверждённые открытия окон (verify рецептов). До неё рецепты
   лавок заблокированы, market — нет.

## Модели окон

- `market.yaml`: удалены `market_pic` и переход
  `recover_closed --click market_pic--> list__tab_home`; сигнатуры
  `recover_closed` пересобраны без HUD-иконок (набор — разметчик из
  сырья `scr_menu_closed` и др.).
- `shop_buy.yaml`/`shop_sell.yaml`: удалены HUD-элементы
  `open_buy_trade`/`open_sale_trade`; HUD-кропы quick-slot перенесены в
  `navigation.yaml`.
- `KNOWN_GAPS.yaml`: п. 11 закрывается правкой модели; п. 3 дополняется
  развязкой (межоконные переходы открытия — рецепты navigation.yaml).

## Инварианты (сохраняются)

Никаких sleep (только wait_until); verify на каждый шаг; никаких
абсолютных координат вне слоя якоря/search_area; трёхзначный исход
OK/FAILED/UNKNOWN; слепых кликов нет; TDD; детерминизм тестов (replay);
код и комментарии на русском. Открытие окна — обратимое действие,
`IrreversibleGuard` не задействован.

## Трёхзначность шагов

| Ситуация | Исход |
|---|---|
| `key X` нажата, verify меню исполнялся весь таймаут и не сошёлся | FAILED, повтор безопасен |
| HID-сбой при нажатии/клике | UNKNOWN (`unconfirmed`) |
| Иконка не локализована в `search_area` | FAILED, клик не выполнялся |
| Клик ушёл, verify окна исполнялся весь таймаут и не сошёлся | FAILED (эффект опровергнут) |
| Отмена (kill switch) до/во время шага | отмена (`cancelled`), эффект не подтверждён |

Граница FAILED/UNKNOWN по инварианту 4: FAILED — эффект опровергнут
наблюдением (verify выполнялся на свежих кадрах весь таймаут); UNKNOWN —
подтвердить невозможно (транспортный сбой HID, отмена). Первичная
формулировка дизайна («клик ушёл, окно не появилось → UNKNOWN») уточнена
при реализации: рецептный verify непрерывен, поэтому неоткрытие за таймаут
— опровергнутый эффект, не неподтверждённый.

## Не-цели

Хоткей-путь лавок (1–3/F1-F3); моделирование окон истории торговли
(KNOWN_GAPS п. 1); чтение строк на живых кадрах (KNOWN_GAPS п. 12);
изменение формата `states`/`transitions` окон.
