# Proposal: core-market-driver

## Why

Большой бот для торговли в Lineage 2 разбит на модули, но ядра, управляющего
внутриигровыми торговыми окнами, пока нет: стратегии торговли не имеют стабильного
API поверх UI игры, а любой патч игры ломает размазанный по модулям код кликов и
чтения экрана. Нужен драйвер трёх торговых окон («Обзор лавок», «Торговая лавка
(Купить)», «Торговая лавка (Продажа)»), который выполняет действия с проверкой
результата, отдаёт модулям торговли стабильный API и позволяет прогонять сценарии
на записанных скриншотах без железа.

Источник: одобренный дизайн `docs/superpowers/specs/2026-11-08-core-market-design.md`
(builder-check пройден, открытые вопросы закрыты, внешние ревью интегрированы).

## What Changes

- Новый Python-пакет `l2core/` (Python 3.10+, код и комментарии на русском, pytest):
  слои `model/`, `detector/`, `primitives/`, `scenarios/`, `adapters/`, `api/`.
- Декларативная UI-модель окон (YAML): элементы с rect'ами от якоря окна, визуальные
  варианты, сигнатуры состояний (минимум два независимых признака), простые переходы
  `(state, action) -> (expected, verify, timeout, on_fail[])`, OCR-регионы с
  грамматиками, геометрия таблицы (`table_geometry`).
- Конвертер/валидатор UI-модели из сырья `meta.json` + `base_screenshot/scr/`
  (кропы копируются в `assets/`, конвертер — «помощник импорта» с diff-отчётом,
  ручные правки не перезаписывает; валидатор гоняется в тестах).
- Детектор окон и состояний: поиск окна игры через Win32, поиск окна торговли по
  якорю (template matching, numpy-only `detect_window()` как дешёвый первый этап),
  параметризованные состояния `window=market.list, params={tab, filter, search,
  scroll_pos…}`, статусы окна `not_found / occluded_or_unstable / found` + признак
  прогрузки контента, перехватчик неизвестных модалок.
- Примитивы действий (`wait_state`, `click_element`, `ocr_region`, `enter_text`,
  `scroll_list`, `drag_item`, `activate_game`, `wait_event`…) со слоями гарантий:
  `wait_until` вместо `sleep`, verify после каждого действия, retry → `on_fail[]` →
  общий recover (ESC → свободный клик → закрыть окно → переоткрыть через иконку HUD →
  перекалибровка якоря → эскалация), трёхзначный результат `OK / FAILED / UNKNOWN`.
- Ядро API для стратегий: синхронные блокирующие вызовы (`open_market`, `set_tab`,
  `search`, `read_rows`, `setup_sell`, `start_sell`, `read_shop_state`, `get_state`,
  `recover`, `health`) + события двух форм (`on(callback)` push и
  `wait_event(type, timeout)` pull); модель потоков: action executor (единственный
  владелец HID), state observer (фоновый, питает события), event dispatcher, поток
  стратегии — единственный вызывающий блокирующий API.
- Вендоринг замороженной копии CRNN-OCR инференса из `L2-CRNN-MODEL-TRAIN`
  (preprocess + CTC greedy decode + загрузчик чекпоинта, байт-идентично обучению,
  guard-тесты на эталонах; `crnn_best.pt` вне git, путь в конфиге); контракт
  `OcrClient.read(region_img) -> (text, confidence)` с возможностью подмены на
  удалённый сервис; вендоринг кода сегментации таблицы из `L2-CRNN-Dataset-Builder`
  (`rows_and_columns`, `extract_cells`, `trim_to_text`); вендоринг HID-модуля из
  `L2-CRNN-arduino`.
- Абстракции `Screen` / `HidPort`: `MssScreen`, `ReplayScreen` (прогон без железа),
  `RecordingScreen`-декоратор (запись сессий для replay-тестов), `FakeHid`;
  JSONL-лог действий (кадр до/после, действие, verify-результат) с ротацией.
- Безопасность: kill switch (локальный хоткей + глобальный таймаут неактивности) →
  прерывание ожиданий, `hid.release_all()`, увод курсора в безопасную зону, событие
  стратегии; dry-run режим (чтение и детекция без HID); DPI-aware; проверка фокуса
  и неперекрытия окна перед каждым действием с активацией через Win32.
- Конфиг `config.yaml`: тайминги/таймауты, пороги и перечитывания OCR, поведенческий
  профиль (доли способов ввода цены, джиттеры), пути (модель, порт arduino),
  kill switch, референсное разрешение 1920×1080.
- MVP-сценарии: `scan_market` (табы, фильтры, поиск, скролл, чтение строк),
  `setup_sell_shop` (выставление своей лавки продажи), `monitor_shop` (детекция
  продаж перечитыванием окна); сценарий `recover`.
- Обязательные артефакты репо: AGENTS.md (команды, инварианты, правила изменений)
  и README (быстрый старт) — создаются в первой задаче, обновление AGENTS.md —
  часть DoD каждой ломающей задачи.

## Capabilities

### New Capabilities

- `ui-model`: декларативная YAML-модель трёх торговых окон и HUD-элементов,
  конвертер из meta.json, валидатор, assets с кроп-шаблонами.
- `window-state-detection`: детекция окна игры и окон торговли, параметризованные
  состояния, статусы окна, перехватчик модалок, конфликт-сигнатуры → unknown.
- `action-primitives`: примитивы действий с verify/retry/on_fail, трёхзначный
  результат, recover-цепочка, кэш кадра в транзакции, работа с hover/тултипами.
- `core-api-events`: синхронный API для стратегий, события push/pull, модель
  потоков (executor/observer/dispatcher), журнал событий.
- `ocr-reading`: вендоренный CRNN-OCR (in-process), грамматики регионов, обработка
  низкого confidence, golden-набор и OCR-бенчмарк, чтение строк таблицы (Row,
  snapshot_id, дедуп по icon_hash).
- `market-scenarios`: MVP-сценарии scan_market, setup_sell_shop, monitor_shop как
  композиции примитивов без внутреннего состояния.
- `replay-logging`: абстракции Screen/HidPort (Mss/Replay/Recording/FakeHid),
  рекордер сессий, JSONL-логирование действий с ротацией.
- `safety`: kill switch, dry-run, фокус/DPI-aware, безопасное состояние HID.

## Impact

- **Репозиторий**: `E:\L2-CRNN-core-market` (новый код целиком).
- **Зависимости**: Python 3.10+, pytest, mss, numpy, opencv-python (template
  matching, если numpy-only ощутимо хуже), torch (инференс CRNN; GPU на этом
  компьютере, CPU-режим обязан работать), pygetwindow/win32gui (Win32), PyYAML.
- **Соседние репозитории** (только источники для вендоринга, не runtime-зависимости):
  `E:\L2-CRNN-arduino` (HID-модуль), `E:\L2-CRNN-MODEL-TRAIN` (OCR-препроцесс,
  CTC-декодер, загрузчик чекпоинта), `E:\L2-CRNN-Dataset-Builder` (сегментация
  таблицы, `build_dataset.py`).
- **Вне git**: `crnn_best.pt` (путь в конфиге), записанные сессии replay-рекордера
  (ротация логов).
- **API**: стабильный контракт для будущих модулей стратегий торговли (вне этого
  изменения).
- **Совместимость**: референс 1920×1080, окна торговли не масштабируются;
  один бот — один компьютер — одно окно игры (мультиклиент — не-цель v1).
