# Design: core-market-driver

Технический дизайн перенесён из одобренного документа
`docs/superpowers/specs/2026-11-08-core-market-design.md` (статус: на ревью пройдено,
builder-check пройден, внешние ревью deepseek/qwen интегрированы). Решения ниже —
авторитетны и не переоткрываются.

## Context

Ядро торгового бота Lineage 2: драйвер трёх внутриигровых окон — «Обзор лавок»
(market), «Торговая лавка (Купить)» (shop_buy, лавка-выкуп), «Торговая лавка
(Продажа)» (shop_sell). Стратегии торговли (что покупать/продавать, цены,
маршрутизация) — вне ядра, сменными модулями поверх стабильного API. Всё знание об
UI вынесено в машиночитаемую UI-модель; ядро — её интерпретатор плюс примитивы.

Сырьё: 39 скриншотов в `base_screenshot/scr/` + мета-разметка (meta.json), кропы
HUD-иконок уже есть в мете (scr_153511). Чекпоинт CRNN `crnn_best.pt`
(val exact 0.983) уверенно читает подписи окон продажи. Константы геометрии таблицы
откалиброваны под скрины 1136×833 — перекалибровка под референс 1920×1080 делается
на этапе построения модели и закрепляется golden-тестами.

## Goals / Non-Goals

**Goals:**
- Каждое действие верифицируется; любой сбой ведёт в диагностируемый recover.
- Расширение без кода в общем случае: новый элемент/состояние/окно = правка
  UI-модели; новая фича = примитив или сценарий.
- Replay любого сценария на записанных кадрах без arduino и игры.
- Стабильный интерфейс для модулей торговли: синхронный Python API + события
  (push и pull).

**Non-Goals (v1):**
- Стратегии, ценообразование, списки предметов, аналитика.
- Открытие чужих лавок из обзора (обзор = только разведка цен). Вывеска и История:
  кнопки известны модели, сценарии не пишутся.
- Мультиклиент; отдельный OCR-сервис (разъём `OcrClient` закладываем).

## Decisions

1. **Гибридная архитектура (модель + код).** Модель отвечает на «где и как
   выглядит» (окна, элементы, rect'ы от якоря, варианты normal/active/disabled,
   сигнатуры состояний, OCR-регионы, простые переходы). Код — на «что делать»
   (примитивы и сценарии со сложной динамикой). Отвергнуты: полный интерпретатор
   (свой DSL предикатов — overengineering для трёх окон) и код-first (патч игры
   ломает ядро).
2. **Слои, зависимости только вниз**: стратегии → сценарии → примитивы →
   интерпретатор UI-модели → Screen/Detector/OcrClient/HidPort → адаптеры
   (MssScreen/ReplayScreen, TemplateMatcher, TorchOcr/RemoteOcr(позже), HidArduino).
   Пакет плоский: `l2core/` с подпакетами `model/`, `detector/`, `primitives/`,
   `scenarios/`, `adapters/`, `api/`.
3. **OCR in-process.** Вендорится замороженная байт-идентичная копия preprocess +
   CTC greedy decode + загрузчик чекпоинта из `L2-CRNN-MODEL-TRAIN` (guard-тесты
   на эталонных векторах; guard-тест обёртки на эталонных кропах в
   `assets/ocr_golden/`). `crnn_best.pt` вне git, путь в конфиге. Torch грузится
   один раз; авто-детект устройства, CPU-режим обязан работать. Контракт:
   `OcrClient.read(region_img) -> (text, confidence)`.
4. **Одно окно игры, оконный режим.** Якорь окна ищется на каждом кадре, кэша
   позиции между кадрами нет. Референс 1920×1080; окна торговли не масштабируются —
  коэффициент масштаба не нужен. Клиентская область — Win32 по заголовку; окно
   торговли внутри — template matching по заголовку окна; numpy-only
   `detect_window()` (яркие линии рамки) — первый дешёвый этап для «Обзора лавок».
   Все координаты элементов 1:1 от якоря своего окна; HUD-элементы ищутся
   template matching'ом по клиентской области в заданной моделью области поиска
   (панели игры перетаскиваются — фиксированных смещений нет).
5. **Фокус перед каждым действием**: окно игры активно и не перекрыто; иначе
   активация через Win32 (SetForeground, retry + эскалация). Не удалось —
   recover/пауза. Процесс DPI-aware; запуск бота с правами не ниже игры.
6. **Протоколы действий**: никаких `sleep` — только `wait_until(predicate,
   timeout)`, таймауты из конфига; verify после каждого действия; retry (n из
   конфига) → `on_fail[]` из перехода → общий recover. Recover-цепочка: ESC →
   клик в свободную область → закрыть окно (если открыто не то) → переоткрыть
   через иконку HUD (open_market/open_shop_buy/open_shop_sell + wait verify) →
   перекалибровка якоря → эскалация (пауза + событие стратегии). Предусловия
   открытия (зона торговли, живой персонаж): неоткрытие окна за таймаут —
   штатный FAILED + событие escalation, без повторных кликов.
7. **Трёхзначный результат критичных действий: OK / FAILED / UNKNOWN.** UNKNOWN =
   эффект не подтверждён (лаг, перекрытие). Потенциально необратимые действия
   (начать продажу, подтвердить) при UNKNOWN не повторяются — решение за
   стратегией. Kill switch прерывает блокирующий вызов, возвращает
   UNKNOWN/CANCELLED, HID освобождается.
8. **Модель потоков**: action executor — единственный владелец HID; state
   observer — фоновый поток, читает экран, не шлёт действия, питает события;
   event dispatcher — очередь; callbacks доставляются в поток стратегии; поток
   стратегии — единственный вызывающий блокирующий API. Мониторы имеют право на
   внутреннее состояние (базовая линия для «продано»); примитивы и сценарии —
   нет (состояние всегда спрашивается у детектора).
9. **Параметризованные состояния**: детектор возвращает `window=market.list,
   params={tab, global_filter, filter, search, scroll_pos…}`, а не имя из огромного
   списка. Сигнатуры окна отделены от значений параметров (активный таб — по
   active-кропам).
10. **Статусы окна тоньше, чем no_window**: `not_found` / `occluded_or_unstable` /
    `found` + признак «контент прогрузился» (verify контентных сигнатур). Recover
    начинается с пассивных шагов; клик по заголовку торгового окна для подъёма —
    допустим; ничего не перетаскивать автоматически.
11. **UI-модель**: YAML (формат читаемее JSON; гранулярность файлов — за
    исполнителем). meta.json — сырьё, не зависимость: конвертер/валидатор подтягивает
    кропы в `assets/`, собирает карточки элементов, проверяет rect'ы и сигнатуры;
    ядро без меты и скриншотов работает самодостаточно. Конвертер — «помощник
    импорта» с diff-отчётом, ручные правки не перезаписывает; шаблоны в `assets/`
    версионируются вместе с моделью.
12. **Сегментация таблицы**: вендоринг `rows_and_columns`, `extract_cells`,
    `trim_to_text` из `L2-CRNN-Dataset-Builder/build_dataset.py`; константы
    (`COL_SEPS`, `ROW_Y0`, `ROW_PITCH`, `MAX_ROWS`, зоны текста) поднимаются в
    `table_geometry` UI-модели; рантайм и обучение используют одинаковую нарезку.
13. **Template matching**: OpenCV `matchTemplate` (TTM_CCOEFF_NORMED) — допустимо,
    если numpy-only альтернатива ощутимо хуже.
14. **Ввод цены/текста**: ядро само выбирает способ (клики по экранному нумпаду
    или клавиатура) по настраиваемому распределению; поиск — Enter или кнопка
    «Поиск», выбор рандомизацией поведенческого профиля (антидетект). Восстановление
    раскладки: OCR поля ввода после набора; транслит → backspace + switch_layout +
    повтор.
15. **Модалки**: универсальный перехватчик «всплыло неизвестное окно» → снимок,
    лог, recover; конкретные типы добавляются в модель по мере досъёмки.
16. **Kill switch**: локальный хоткей (слушаем клавиатуру, не через arduino) +
    глобальный таймаут неактивности; мгновенный стоп цикла, `hid.release_all()`,
    курсор в безопасную точку, событие стратегии.
17. **Dry-run**: конфиг-флаг; экран читается, состояние определяется, действия
    только логируются (без HID) — для первых запусков на живой игре.
18. **Кэш кадра в рамках транзакции**: один grab → analyze once; перед необратимым
    действием — свежий grab и re-verify цели.
19. **Replay и логирование**: абстракция `Screen` (MssScreen / ReplayScreen),
    `RecordingScreen`-декоратор пишет кадры+действия+результаты в сессии;
    JSONL-лог каждого действия (кадр до/после, действие, verify-результат) с
    ротацией и ограничением размера (только ключевые кадры). FakeHid поверх
    эмулятора из L2-CRNN-arduino для юнит-тестов.
20. **Конфиг** `config.yaml`: тайминги/таймауты, порог confidence OCR и число
    перечитываний, поведенческий профиль (доли способов ввода, джиттеры,
    человеческие тайминги HID), пути (модель CRNN, порт arduino), kill switch,
    референсное разрешение.
21. **Репозиторий**: `E:\L2-CRNN-core-market`, Python 3.10+, код и комментарии на
    русском, pytest, TDD, детерминизм тестов. AGENTS.md и README — обязательные
    артефакты первой задачи; обновление AGENTS.md — часть DoD ломающих задач.

## Роли окон (критично, подтверждено владельцем)

- «Обзор лавок» — только разведка цен; чужие лавки из обзора НЕ открываются.
- shop_buy = лавка-выкуп (твои цены закупки); shop_sell = лавка продажи.
- Перенос предметов в лавку и обратно — drag.

## Контракты (детали из ревью)

- `Row`: словарь ячеек по именам колонок модели + `screen_y` + `icon_hash`
  (pHash иконки, дедуп между кадрами скролла) + `partial: bool`; `read_rows`
  возвращает `snapshot_id` (рынок меняется во время сканирования — стратегия
  сверяет).
- Цены: грамматика региона (разделители `,` `.`, суффиксы `к`/`кк`), валидация
  по диапазону; несовпадение → перечитывание, при повторе — низкий conf.
- `scroll_list(dir, n)`: единица n = щелчок колеса; конец списка — по признаку
  модели (стрелка «вниз» disabled / пустая область), не только сравнением строк.
- Позиция скролла: кропы «прокрутка вверх/вниз» (есть в мете) + сравнение нижней
  видимой строки между кадрами.
- События: `sold`, `window_closed`, `modal`, `recovered`, `escalation`, `killed`;
  полезная нагрузка фиксируется в API-справочнике (пишется вместе с кодом).
- `slot` (для setup_sell): координаты ячейки генерируются из геометрии сетки
  лавки, не размечаются вручную.
- Обработка низкого confidence OCR: до N перечитываний с увеличением региона →
  исключение стратегии с диагностикой.

## Риски / Trade-offs

- **OpenCV-зависимость** (новая) → принята, если numpy-only matchTemplate ощутимо
  хуже; решается замером на этапе детектора.
- **Константы геометрии откалиброваны под 1136×833** → перекалибровка под
  1920×1080 из меты + golden-тесты; рассинхрон с обучением исключён общим
  источником констант (экспорт в датасет-пайплайн с пометкой версии и diff-отчётом).
- **Числовые значения CRNN не проверены** (подписи читаются conf 0.98–0.999,
  цифры — нет) → контрольная проверка на доснятых кропах, guard-тесты на
  `assets/ocr_golden/`, OCR-бенчмарк на CPU и GPU.
- **Семантика переходов пуста в мете** (`click_leads_to: null`) → описывается
  владельцем по знанию игры + досъёмка; до закрытия переходы с verify/on_fail в
  модели не считаются завершёнными.
- **Входящий поток кадров для replay** — только 39 статичных скриншотов →
  RecordingScreen-декоратор пишет живые сессии; replay-тесты сценариев появляются
  после первых записей (юнит-тесты детектора — сразу на 39 скриншотах).
- **hover меняет вид элемента, тултип перекрывает цель, мигающая каретка ломает
  OCR поля** → verify после hover-паузы; сдвиг курсора/ожидание исчезновения
  тултипа; стабилизация кадра двумя одинаковыми чтениями; ротация и размер логов
  кадров ограничены.
- **SetForeground может не сработать** → retry + эскалация; заблокированный
  экран/оверлеи → осмысленная ошибка, не слепые клики.

## Migration Plan

Зелёное поле: новый репозиторий, существующих спецификаций и кода нет. Порядок —
по tasks.md: инфраструктура (пакет, конфиг, AGENTS.md/README) → модель и
конвертер → адаптеры/детектор → OCR → примитивы → сценарии → API/потоки →
безопасность → replay/рекордер. Откат: удаление change-директории и ветки;
внешние системы не затрагиваются.
