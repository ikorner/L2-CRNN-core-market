# Spec: ocr-reading

## ADDED Requirements

### Requirement: OCR in-process на замороженной копии обучающего кода
Система SHALL вендорить байт-идентичную копию preprocess + CTC greedy decode + загрузчик чекпоинта/алфавита из `L2-CRNN-MODEL-TRAIN`; guard-тест SHALL проверять эталонные вектора; файл `crnn_best.pt` SHALL храниться вне git с путём в конфиге; torch SHALL загружаться один раз с авто-детектом устройства (GPU на этом компьютере), CPU-режим обязан работать.

#### Scenario: Guard-тест эталонных векторов
- **WHEN** запускается guard-тест OCR-препроцесса
- **THEN** результаты на эталонных входах байт-идентичны обучающему коду

#### Scenario: Загрузка на CPU
- **WHEN** GPU недоступен и в конфиге авто-детект
- **THEN** инференс выполняется на CPU без падения

### Requirement: Контракт OcrClient с возможностью подмены реализации
Интерфейс `OcrClient` SHALL иметь контракт `read(region_img) -> (text, confidence)` и позволять подменить реализацию (in-process → удалённый сервис) без правки ядра; OCR-вызовы вне контракта MUST быть запрещены.

#### Scenario: Подмена реализации
- **WHEN** конфигурация указывает другую реализацию `OcrClient`
- **THEN** ядро использует её без изменения кода сценариев и примитивов

### Requirement: Грамматики OCR-регионов и валидация значений
OCR-регионы модели SHALL задавать грамматику ожидаемого результата (`digits`, `price`, `text`); цены SHALL валидироваться по диапазону с учётом разделителей (`,` `.`), суффиксов (`к`/`кк`) и составной игровой записи «x млрд y млн z тыс d аден» (сумма компонентов, масштабы строго по убыванию, голое число в середине последовательности — несовпадение); несовпадение грамматики SHALL приводить к перечитыванию, при повторе — к низкому confidence.

#### Scenario: Чтение цены с суффиксом
- **WHEN** регион цены содержит «1.5кк»
- **THEN** результат валиден по грамматике price и находится в допустимом диапазоне

#### Scenario: Чтение цены в составной игровой записи
- **WHEN** регион цены содержит «5 млрд 450 млн 300 тыс 100 аден»
- **THEN** результат валиден и равен 5_450_300_100; «5 тыс 100 аден» валиден и равен 5100; «5 100 тыс аден» (потерянное слово) — несовпадение грамматики

#### Scenario: Нарушение грамматики
- **WHEN** результат не соответствует грамматике региона
- **THEN** выполняется перечитывание с увеличением региона, при повторе фиксируется низкий confidence

### Requirement: Обработка низкого confidence
При confidence ниже порога из конфига ядро SHALL выполнять до N перечитываний с увеличением региона, затем возвращать исключение стратегии с диагностикой; порог и N SHALL быть конфигурируемы.

#### Scenario: Исчерпание перечитываний
- **WHEN** после N перечитываний confidence ниже порога
- **THEN** стратегия получает исключение с диагностикой региона и значениями

### Requirement: Стабилизация кадра для мигающей каретки
Для OCR полей ввода система SHALL стабилизировать кадр: два подряд одинаковых чтения считаются стабильным результатом; плейсхолдер SHALL отличаться от введённого текста.

#### Scenario: Мигающая каретка
- **WHEN** OCR поля ввода даёт разные результаты между кадрами из-за каретки
- **THEN** чтение повторяется до двух одинаковых результатов подряд

### Requirement: Чтение строк таблицы с Row и дедупликацией
`read_rows()` SHALL возвращать строки как `Row`: словарь ячеек по именам колонок модели + `screen_y` + `icon_hash` (pHash иконки предмета) + `partial: bool` для обрезанных краевых строк; дедупликация одинаковых строк между кадрами скролла SHALL выполняться по `icon_hash` + цене + `y`; возвращаемый результат SHALL включать `snapshot_id`.

#### Scenario: Дедуп одинаковых строк при скролле
- **WHEN** один и тот же предмет виден на двух соседних кадрах скролла
- **THEN** строки с совпадающими `icon_hash`, ценой и положением не дублируются в общем выводе

### Requirement: Golden-набор и OCR-бенчмарк
Guard-тест обёртки SHALL держать набор эталонных кропов с известным текстом в `assets/ocr_golden/`; SHALL выполняться OCR-бенчмарк на golden-наборе (точность и время на CPU и GPU), включая контрольную проверку чтения числовых значений (цены, «0 из N», адена) на доснятых кропах.

#### Scenario: Бенчмарк на golden-наборе
- **WHEN** запускается OCR-бенчмарк
- **THEN** выводится точность и время инференса отдельно на CPU и GPU по эталонным кропам
