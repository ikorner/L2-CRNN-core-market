# Spec: window-state-detection

## ADDED Requirements

### Requirement: Детектор находит окно игры и окно торговли на каждом кадре
Детектор SHALL на каждом запрошенном кадре находить окно игры через Win32 (заголовок, клиентская область, проверка «не свёрнуто») и внутри него окно торговли по якорю (template matching по заголовку «Обзор лавок» / «Торговая лавка»; numpy-only `detect_window()` — первый дешёвый этап для обзора); кэш позиции окна между кадрами MUST NOT использоваться.

#### Scenario: Окно торговли найдено по якорю
- **WHEN** на кадре открыто окно «Обзор лавок» и окно игры активно
- **THEN** детектор возвращает `found` и координаты якоря окна

#### Scenario: Окно игры свёрнуто
- **WHEN** окно игры свёрнуто или не найдено по заголовку
- **THEN** детектор возвращает статус `not_found` с диагностикой причины

### Requirement: Детектор возвращает параметризованные состояния
Детектор SHALL возвращать состояние в виде `(window, params)`, где params включает `tab`, `global_filter`, `filter`, `search`, `scroll_pos` и прочие параметры модели; активный таб и фильтры SHALL определяться по active-кропам элементов; сигнатуры окна MUST быть отделены от значений параметров.

#### Scenario: Определение активного таба
- **WHEN** открыт обзор лавок на табе «Оружие»
- **THEN** детектор возвращает `window=market.list` и `params.tab` соответствующий «Оружию»

#### Scenario: Несовпадение с ожиданием
- **WHEN** детектор не может подтвердить ожидаемое окно/параметры
- **THEN** возвращается состояние `unknown`

### Requirement: Каждое состояние имеет минимум два независимых признака
Детекция состояния SHALL требовать минимум два независимых визуальных признака из иерархии «пиксель-пробы → template matching → OCR-строки»; при противоречии признаков друг другу SHALL возвращаться `unknown`, а не уверенное решение.

#### Scenario: Конфликт сигнатур
- **WHEN** один признак указывает на market, другой противоречит ему
- **THEN** детектор возвращает `unknown` с журналированием конфликтующих признаков

### Requirement: Статусы окна включают нестабильность и прогрузку контента
Детектор SHALL различать статусы `not_found` (закрыто/нет на экране), `occluded_or_unstable` (якорь мерцает / перекрыто игровым окном или тултипом) и `found` (шаблон совпал); помимо статуса SHALL проверяться признак «контент прогрузился» по контентным сигнатурам, а не только по заголовку окна.

#### Scenario: Мерцающий якорь
- **WHEN** шаблон заголовка совпадает нестабильно между двумя кадрами подряд
- **THEN** возвращается `occluded_or_unstable`, а не `found`

#### Scenario: Заголовок есть, контент не прогрузился
- **WHEN** заголовок окна найден, но контентные сигнатуры отсутствуют
- **THEN** состояние помечается как «контент не прогружен» до появления контентных признаков

### Requirement: Перехватчик неизвестных модалок
Система SHALL перехватывать внешний контур/текст, не принадлежащий известным окнам, как `modal.unknown`: снимок в лог, журналирование, переход в recover; известные типы модалок SHALL добавляться в модель по мере досъёмки.

#### Scenario: Всплыла неизвестная модалка
- **WHEN** на кадре обнаружен контур/текст вне известных окон
- **THEN** фиксируется снимок в лог, состояние становится `modal.unknown` и запускается recover

### Requirement: Детектор покрыт тестами на существующих скриншотах
Для каждого из 39 существующих скриншотов в `base_screenshot/scr/` SHALL существовать тест с ожидаемым `(window, params)` по мере разметки меты.

#### Scenario: Скриншот определяется как ожидается
- **WHEN** детектор анализирует размеченный скриншот
- **THEN** результат `(window, params)` совпадает с разметкой
